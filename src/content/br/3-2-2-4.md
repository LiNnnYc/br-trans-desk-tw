> **Validation of Domain Authorization or Control**

> This section defines the permitted processes and procedures for validating the Applicant's ownership or control of the domain.

本節定義了驗證申請者（Applicant）對網域之所有權或控制權的允許程序與步驟。

> The CA SHALL confirm that prior to issuance, the CA has validated each Fully-Qualified Domain Name (FQDN) listed in the Certificate as follows:

憑證機構（Certification Authority，CA）**應（SHALL）**確認在簽發前，CA 已依下列方式驗證憑證中列出的每個完全吻合網域名稱（Fully-Qualified Domain Name，FQDN）：

> 1. When the FQDN is not an Onion Domain Name, the CA SHALL validate the FQDN using at least one of the methods listed below; and

1. 當 FQDN 不是 Onion 網域名稱（Onion Domain Name）時，CA **應（SHALL）**使用至少一種下方列出的方法驗證該 FQDN；且

> 2. When the FQDN is an Onion Domain Name, the CA SHALL validate the FQDN in accordance with Appendix B.

2. 當 FQDN 為 Onion 網域名稱（Onion Domain Name）時，CA **應（SHALL）**依據附錄 B 驗證該 FQDN。

> Completed validations of Applicant authority may be valid for the issuance of multiple Certificates over time. In all cases, the validation must have been initiated within the time period specified in the relevant requirement (such as Section 4.2.1 of this document) prior to Certificate issuance. For purposes of domain validation, the term Applicant includes the Applicant's Parent Company, Subsidiary Company, or Affiliate.

已完成的申請者權限驗證得於一段時間內對多次憑證簽發有效。在所有情況下，驗證必須在憑證簽發前，於相關規定（例如本文件的第 4.2.1 節）指定的期間內發起。就網域驗證（Domain Validation）之目的而言，「申請者」一詞包含申請者的母公司（Parent Company）、子公司（Subsidiary Company）或關係企業（Affiliate）。

> Effective 2026-03-15: DNSSEC validation back to the IANA DNSSEC root trust anchor MUST be performed on all DNS queries associated with the validation of domain authorization or control by the Primary Network Perspective. The DNS resolver used for all DNS queries associated with the validation of domain authorization or control by the Primary Network Perspective MUST:

自 2026-03-15 起生效：由 主要網路視角（Primary Network Perspective）進行之與網域授權或控制驗證相關的所有 DNS 查詢，**應（MUST）**執行回溯至 IANA DNSSEC 根信賴根（IANA DNSSEC root trust anchor）的 DNSSEC 驗證。由 主要網路視角（Primary Network Perspective）用於與網域授權或控制驗證相關的所有 DNS 查詢 之 DNS 解析器（DNS resolver） **應（MUST）**：

> - perform DNSSEC validation using the algorithm defined in RFC 4035, Section 5; and

- 使用 RFC 4035 第 5 節定義的演算法執行 DNSSEC 驗證；且

> - support NSEC3 as defined in RFC 5155; and

- 支援 RFC 5155 定義的 NSEC3；且

> - support SHA-2 as defined in RFC 4509 and RFC 5702; and

- 支援 RFC 4509 與 RFC 5702 定義的 SHA-2；且

> - properly handle the security concerns enumerated in RFC 6840, Section 4.

- 妥善處理 RFC 6840 第 4 節中列舉的安全疑慮。

> Effective 2026-03-15: 

自 2026-03-15 起生效：

> For e-mail Domain Validation methods described in sections 3.2.2.4.4, 3.2.2.4.13, 3.2.2.4.14, DNSSEC validation back to the IANA DNSSEC root trust anchor MUST be performed on all DNS CNAME, CAA, TXT queries attempting to obtain the Authorization Domain Name associated with the validation of domain authorization or control by the Primary Network Perspective and CAs MUST NOT use local policy to disable DNSSEC validation. For all other DNS queries, DNSSEC validation back to the IANA DNSSEC root trust anchor SHOULD be performed and CAs SHOULD NOT use local policy to disable DNSSEC validation.

對於第 3.2.2.4.4、3.2.2.4.13、3.2.2.4.14 節中描述的電子郵件網域驗證方法，針對由 主要網路視角（Primary Network Perspective）試圖取得與網域授權或控制驗證相關之經授權網域名稱（Authorization Domain Name）的所有 DNS CNAME、CAA、TXT 查詢，**應（MUST）**執行回溯至 IANA DNSSEC 根信賴根（IANA DNSSEC root trust anchor）的 DNSSEC 驗證，且 CA **不得（MUST NOT）**使用 本地政策 停用 DNSSEC 驗證。對於所有轉發 DNS 查詢，**宜（SHOULD）**執行回溯至 IANA DNSSEC 根信賴根（IANA DNSSEC root trust anchor）的 DNSSEC 驗證，且 CA **不宜（SHOULD NOT）**使用 本地政策 停用 DNSSEC 驗證。

> For all other Domain Validation methods, DNSSEC validation back to the IANA DNSSEC root trust anchor MUST be performed on all DNS queries associated with the validation of domain authorization or control by the Primary Network Perspective and CAs MUST NOT use local policy to disable DNSSEC validation on any DNS query associated with the validation of domain authorization or control.

對於所有其他網域驗證方法，由 主要網路視角（Primary Network Perspective）進行之與網域授權或控制驗證相關的所有 DNS 查詢，**應（MUST）**執行回溯至 IANA DNSSEC 根信賴根（IANA DNSSEC root trust anchor）的 DNSSEC 驗證，且 CA **不得（MUST NOT）**在任何與網域授權或控制驗證相關的 DNS 查詢 上使用 本地政策 停用 DNSSEC 驗證。

> DNSSEC validation back to the IANA DNSSEC root trust anchor is considered outside the scope of self-audits performed to fulfill the requirements in Section 8.7.

回溯至 IANA DNSSEC 根信賴根的 DNSSEC 驗證，被視為超出為符合第 8.7 節要求而執行之自我稽核（self-audits）的範圍。

> DNSSEC validation back to the IANA DNSSEC root trust anchor is considered outside the scope of the logging requirements of Section 5.4.1.

回溯至 IANA DNSSEC 根信賴根的 DNSSEC 驗證，被視為超出第 5.4.1 節紀錄要求（logging requirements）的範圍。

> **Note**: FQDNs may be listed in Subscriber Certificates using dNSNames in the subjectAltName extension or in Subordinate CA Certificates via dNSNames in permittedSubtrees within the Name Constraints extension.

**註**：FQDN 得透過 subjectAltName 延伸欄位中的 dNSName 列於用戶憑證（Subscriber Certificates）中，或透過 名稱限制（Name Constraints）延伸欄位中 permittedSubtrees 的 dNSName 列於下屬憑證機構憑證（Subordinate CA Certificates）中。
