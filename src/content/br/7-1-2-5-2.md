> **Technically Constrained TLS Subordinate CA Name Constraints**

> For a TLS Subordinate CA to be Technically Constrained, Name Constraints extension MUST be encoded as follows. As an explicit exception from [RFC 5280](https://datatracker.ietf.org/doc/html/rfc5280), this extension SHOULD be marked critical, but MAY be marked non-critical if compatibility with certain legacy applications that do not support Name Constraints is necessary.

TLS 下屬憑證機構若欲被認定為技術受限，名稱限制延伸欄位**應（MUST）**依以下方式編碼。作為 RFC 5280 之明確例外，本延伸欄位**宜（SHOULD）**標記為關鍵，但若需與某些不支援名稱限制之舊有應用程式相容，**得（MAY）**標記為非關鍵。

表：`nameConstraints` 要求

| **欄位** | **說明** |
| ---- | ------ |
| `permittedSubtrees` | `permittedSubtrees` **應（MUST）**包含至少一個適用於 `dNSName` 及 `iPAddress` `GeneralName` 名稱類型的 `GeneralSubtree`，除非該 `GeneralName` 名稱類型出現於 `excludedSubtrees` 中以排除該類型之所有名稱。此外，`permittedSubtrees` **應（MUST）**包含至少一個 `directoryName` `GeneralName` 名稱類型的 `GeneralSubtree`。 |
|     `GeneralSubtree` | 出現於 `permittedSubtrees` 中之 `GeneralSubtree` 的要求。 |
|         `base` | 參見下表。 |
|         `minimum` | **不得（MUST NOT）**存在。 |
|         `maximum` | **不得（MUST NOT）**存在。 |
| `excludedSubtrees` | `excludedSubtrees` **應（MUST）**包含至少一個適用於 `dNSName` 及 `iPAddress` `GeneralName` 名稱類型的 `GeneralSubtree`，除非 `permittedSubtrees` 中已存在該名稱類型的實例。不建議（NOT RECOMMENDED）使用 `directoryName` 名稱類型。 |
|     `GeneralSubtree` | 出現於 `permittedSubtrees` 中之 `GeneralSubtree` 的要求。 |
|         `base` | 參見下表。 |
|         `minimum` | **不得（MUST NOT）**存在。 |
|         `maximum` | **不得（MUST NOT）**存在。 |

> The following table contains the requirements for the `GeneralName` that appears within the `base` of a `GeneralSubtree` in either the `permittedSubtrees` or `excludedSubtrees`.

以下表格列出出現於 `permittedSubtrees` 或 `excludedSubtrees` 中 `GeneralSubtree` 之 `base` 內的 `GeneralName` 要求。

表：`base` 欄位之 `GeneralName` 要求

| **名稱類型** | **出現要求** | **允許之子樹** | **排除之子樹** | **完整命名空間排除** |
| --------------- | ------------- | ----------------------- | ------------------------ | ------------------------ |
| `dNSName` | 應（MUST） | CA **應（MUST）**確認申請者已完成 `dNSName` 之註冊，或已獲網域名稱註冊人授權代其行事。參見[第 3.2.2.4 節](#3224-validation-of-domain-authorization-or-control)。 | 若 `permittedSubtrees` 中至少存在一個 `dNSName` 實例，CA **得（MAY）**指定一個或多個下層網域名稱予以排除。 | 若 `permittedSubtrees` 中無任何 `dNSName` 實例，CA **應（MUST）**包含一個零長度 `dNSName`，表示不允許任何網域名稱。 |
| `iPAddress` | 應（MUST） | CA **應（MUST）**確認申請者已獲分配該 `iPAddress` 範圍，或已獲分配者授權代其行事。參見[第 3.2.2.5 節](#3225-authentication-for-an-ip-address)。 | 若 `permittedSubtrees` 中至少存在一個 `iPAddress` 實例，CA **得（MAY）**指定那些範圍的一個或多個子區段予以排除。 | 若 `permittedSubtrees` 中無任何 IPv4 `iPAddress`，CA **應（MUST）**包含一個 8 個零位元組的 `iPAddress`，表示 IPv4 範圍 0.0.0.0/0 均被排除。若無任何 IPv6 `iPAddress`，CA **應（MUST）**包含一個 32 個零位元組的 `iPAddress`，表示 IPv6 範圍 ::0/0 均被排除。 |
| `directoryName` | 應（MUST） | CA **應（MUST）**確認申請者及／或其子公司之名稱屬性，使所有簽發之憑證均符合相關憑證剖繪（參見[第 7.1.2 節](#712-certificate-content-and-extensions)），包含名稱形式（參見[第 7.1.4 節](#714-name-forms)）。 | 不建議（NOT RECOMMENDED）在 `excludedSubtrees` 中包含值。 | CA **應（MUST）**在 `permittedSubtrees` 中包含一個值，因此本情況不適用。詳見排除子樹要求。 |
| `otherName` | 不建議（NOT RECOMMENDED） | 參見下文 | 參見下文 | 參見下文 |
| 任何其他值 | 不得（MUST NOT） | - | - | - |

> Any `otherName`, if present:

任何 `otherName`，若存在：

1. **應（MUST）**適用於公共網際網路環境，除非：
   a. `type-id` 落於申請者能證明擁有所有權之 OID 弧範圍內，或
   b. 申請者能以其他方式證明有權在公開環境中主張該資料。
2. **不得（MUST NOT）**包含會使信賴憑證者對 CA 所驗證之憑證資訊產生誤解之語義。
3. **應（MUST）**依定義該 `otherName` 之 `type-id` 與 `value` 的相關 ASN.1 模組，以 DER 編碼。

> CAs SHALL NOT include additional names unless the CA is aware of a reason for including the data in the Certificate.

CA **不得（SHALL NOT）**納入額外名稱，除非 CA 知悉在憑證中納入該資料之理由。
